# Module 01.04 — Continuous integration

> **Story:** [01 — Foundation](../../stories/01-foundation.md) · **Covers:** S01-AC4, S01-AC5 (both in part; 01.05 and 01.06 complete them) · **Depends on:** 01.02, 01.03
> **Status:** Approved 2026-10-03.

## Purpose

Make every pull request prove itself. CI arrives before the API and the app so that those modules are built under it rather than checked after the fact.

## Responsibilities

- A GitHub Actions workflow that runs on every pull request and on every push to `development` and `main`.
- It installs with the pinned Node and pnpm and runs the root `check` script — nothing else.
- Evidence that each gate present so far can fail: a lint error, a type error, a failing test, and an invalid content file, each seen red in CI.

## Interface

- **CI runs `pnpm check` only.** The workflow file holds no gate logic. A later module adds a gate by extending the root scripts, and CI picks it up unchanged.
- Any service CI must provide to later modules, such as a Postgres container for API tests, is added by the module that needs it.

## Acceptance criteria

- A pull request shows the workflow passing.
- Four deliberately broken pull requests or commits, one per gate, each show the workflow failing for the intended reason. The evidence is linked from the decisions file.
- The workflow uses no secret.

## Out of scope

- The API build gate and the no-persistence greps (01.05).
- The app test and web export gates (01.06).
- Deployment (01.07).
